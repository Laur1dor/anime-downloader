# AnimeDownloader

Русский · [English](README_English.md)

Telegram-бот для поиска и загрузки аниме и сериалов с поддерживаемых сайтов. Выберите озвучку, серии и качество; бот подготовит MP4 и отправит его в Telegram. Владелец дополнительно может сохранять видео в свою медиатеку Jellyfin.

## Возможности

- Ссылки AnimeGO, YummyAnime и отдельный источник «Клана Сопрано».
- Поиск по названию и вариантам названий из каталогов.
- Автоматический выбор подходящего плеера для выбранной озвучки и качества.
- Номера сезонов и серий, постеры и названия эпизодов при доступности метаданных.
- Разделение больших видео на MP4-части без перекодирования; ограниченный дисковый кэш повторной доставки.
- Telegram, медиатека владельца или оба назначения. Обычные пользователи не получают доступ к хранилищу владельца.
- Категории «Аниме», «Сериалы», «Аниме-фильмы», «Фильмы».

Доступность и качество зависят от источника, региона и озвучки. Поддержка сайта не означает поддержку каждого его плеера. Если источник не отвечает, бот сообщает об ошибке; отсутствие ошибок при любых условиях не гарантируется.

## Быстрый старт: Docker Compose

Нужны Linux с Docker Engine и Compose v2, доступ в Telegram и место под исходное видео и его части. Дополнительный торрент-стек не требуется.

1. Склонируйте репозиторий и перейдите в его каталог.
2. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN`, `ADMIN_ID`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`. Последние два значения относятся к приложению Telegram API, а не к боту.
3. Запустите:

```bash
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail=100 bot
```

Начните с `ACCESS_MODE=admin` и `MAX_CONCURRENT_JOBS=1`. Для обычных пользователей включите `ACCESS_MODE=public` после проверки владельцем. Bot API и базу данных не нужно публиковать в интернет: общение контейнеров не требует свободного порта на хосте.

Бот получает Docker socket ради административного перезапуска контейнеров. Этот доступ даёт значительные права на хосте; для установки без этой кнопки удалите монтирование socket и очистите `RELOAD_CONTAINERS` в Compose.

## Jellyfin, NAS и Proxmox

Подключите хранилище на Linux-хосте и проверьте права. Jellyfin должен читать те же файлы, в которые пишет бот. Укажите в `.env`:

```dotenv
LIBRARY_HOST_DIR=/srv/media/Anime
MEDIA_HOST_ROOT=/srv/media
MEDIA_ROOT=/app/media
JELLYFIN_URL=http://jellyfin:8096
JELLYFIN_API_KEY=
```

`jellyfin` — пример DNS-имени: замените на доступный из контейнера адрес сервера. Ключ создаётся в настройках Jellyfin. Затем:

```bash
docker compose -f compose.yml -f compose.library.yml config --quiet
docker compose -f compose.yml -f compose.library.yml up -d --build
```

Отсутствующий NAS нельзя заменять пустой локальной папкой: файлы попадут на системный диск. Перед запуском проверяйте `findmnt`. Медиатека сохраняет целый файл, Telegram может получать части. В Jellyfin создайте библиотеки сериалов для Anime/Series и фильмов для AnimeMovies/Movies; фактические имена каталогов сверяйте с `MEDIA_CATEGORIES` в `animedl/models.py`.

Для Proxmox LXC подключите хранилище на хосте и передайте его через свободный mount point. У непривилегированного LXC проверьте UID/GID. Docker требует правильно настроенного nesting; параметры зависят от версии и политики хоста. Bind mount обычно не входит в резервную копию rootfs: медиатеку резервируйте отдельно. Не создавайте новый пул и не форматируйте диски ради переноса. Конфигурацию Jellyfin также сохраняйте отдельно; аппаратное транскодирование необязательно для прямого воспроизведения совместимого файла.

## Сеть: Россия и другие регионы

Проверяйте отдельно сайт-каталог, плеер/CDN, метаданные и Telegram с самого сервера. Некоторые источники требуют российский IP, другие могут быть недоступны из России. Прокси для всего трафика может сломать ранее работавший источник.

Сначала пробуйте прямое подключение. При необходимости задавайте собственный `ALL_PROXY`/`NO_PROXY` и проверяйте маршрут. Некоторые экстракторы используют прямой доступ намеренно. Бесплатные публичные прокси не являются гарантией работы или конфиденциальности. Конфигурация соседнего контейнера на чужом сервере не является обязательной частью установки.

## Ошибки и восстановление

| Симптом | Проверка |
| --- | --- |
| HTTP 403 до скачивания | Регион, доступность источника, сессия плеера. Это не ошибка размера Telegram. |
| Нет ожидаемого качества | Качество для конкретной озвучки/серии, предупреждение о недоступном плеере, повторная проверка. |
| Не скачалась часть серий | Итоговый отчёт и повтор неудавшихся; не обязательно повторять весь сезон. |
| Файл большой | Наличие `ffmpeg`, место под исходник и части, лимит `MAX_TG_MB`. |
| Тайм-аут отправки | Сначала проверьте чат: Telegram мог принять файл, но не вернуть ответ. Повтор может создать дубль. |
| Кэш не сохранил файл | `RETRY_CACHE_MB`, `RETRY_CACHE_HOURS`, свободное место. По умолчанию до 4 ГБ и 24 часов. |
| Не видно серии в Jellyfin | Сканирование, путь, права чтения и фильтр просмотренных. Отметка «просмотрено» сама не удаляет файл. |
| Нет пропуска заставки | Анализ Intro Skipper, поддержка и настройки клиента. Этот необязательный плагин не входит в стек. |

Разделение без перекодирования зависит от ключевых кадров: если один интервал больше лимита, возможна явная ошибка вместо потери кадров или скрытого снижения качества. Кэш ограничен и не заменяет резервную копию. Для отчёта об ошибке сохраните время, источник, серии и обезличенный лог. Не публикуйте `.env`, ключи, cookies или пользовательские базы.

## Ошибки, действия и статистика

Владелец использует `/stats` и `/errors`; другим пользователям эти команды недоступны. Журнал фиксирует действия, результаты загрузки и доставки, источник, качество, размер и категории. Содержимое сообщений, полные URL, ключи и текст исключений в журнал событий не записываются. Идентификаторы пользователей всё же являются данными пользователей: ограничивайте доступ к БД и сообщайте им о сборе статистики.

Локальный ограниченный SQLite-журнал сохраняется и без PostgreSQL. По умолчанию хранится до 50 000 событий и до 30 дней, регулируется `AUDIT_MAX_EVENTS` и `AUDIT_RETENTION_DAYS`. Статистика команд строится по этому сохранённому срезу, а не за всё время жизни бота. Оповещения об ошибках получает только владелец; одинаковая ошибка ограничена одним оповещением за 30 минут. `AUDIT_ALERTS=0` отключает их.

Для отдельного PostgreSQL задайте в `.env` длинный случайный `AUDIT_POSTGRES_PASSWORD` из букв и цифр, затем добавьте override:

```bash
docker compose -f compose.yml -f compose.observability.yml up -d --build
```

Можно одновременно добавлять `-f compose.library.yml`. PostgreSQL 17 Alpine использует отдельный volume и внутреннюю сеть, без порта на хосте: соседний PostgreSQL на 5432 не мешает. Локальные события переносятся в него асинхронно с устойчивыми идентификаторами и повтором после сбоя. В PostgreSQL действует срок хранения, но не локальный предел числа строк. Отдельно сохраняйте резервные копии: журнал не заменяет backup. Alpine — вариант образа, а не ограничение числа пользователей; нагрузку определяют частота действий, запросы и ресурсы сервера.

Наблюдаемость показывает ошибки и статистику. Она не применяет произвольные изменения к коду автоматически: исправления проходят проверку и обычное обновление с возможностью отката.

## Разработка и CI

Нужны Python 3.13, `ffmpeg`/`ffprobe`:

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium --only-shell
python -m unittest discover -s tests -v
docker build -t anime-downloader-check .
```

GitHub Actions выполняет тесты, включая настоящий `ffmpeg`, и сборку образов без секретов. Сайт для CI не нужен. CI не публикует образ и не обновляет сервер: обновление выполняется отдельно после проверки, с резервной копией и откатом.

Проверки внешних источников проводятся отдельно: unit-тесты и короткий фрагмент не подтверждают отправку целого файла больше 2 ГБ. Используйте только материалы, которые вправе скачивать и хранить.
