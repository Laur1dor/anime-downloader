# AnimeDownloader

Русский · [English](README_English.md)

Telegram-бот для поиска и загрузки аниме и сериалов с поддерживаемых сайтов. Выберите озвучку, серии и качество; бот подготовит MP4 и отправит его в Telegram. Владелец дополнительно может сохранять видео в свою медиатеку Jellyfin.

## Возможности

- Ссылки AnimeGO, YummyAnime и отдельный источник «Клана Сопрано».
- Поиск по названию и вариантам названий из каталогов: страницы по пять результатов, выбор кнопкой-номером или вводом номера, возврат и отмена в одном сообщении.
- Автоматический выбор подходящего плеера для выбранной озвучки и качества.
- Номера сезонов и серий, постеры и названия эпизодов при доступности метаданных.
- Разделение больших видео на MP4-части без перекодирования; ограниченный дисковый кэш повторной доставки.
- Telegram, медиатека владельца или оба назначения. Обычные пользователи не получают доступ к хранилищу владельца.
- Блокировка бота останавливает задачу этого чата и следующие серии; запрет отправки из кэша не запускает повторное скачивание.
- Категории «Аниме», «Сериалы», «Аниме-фильмы», «Фильмы».

Доступность и качество зависят от источника, региона и озвучки. Поддержка сайта не означает поддержку каждого его плеера. Если источник не отвечает, бот сообщает об ошибке; отсутствие ошибок при любых условиях не гарантируется.

## Быстрый старт: Docker Compose

Нужны Linux с Docker Engine и Compose v2, доступ в Telegram и место под исходное видео и его части. Дополнительный торрент-стек не требуется.

1. Склонируйте репозиторий и перейдите в его каталог.
2. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN`, `ADMIN_ID`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`. Последние два значения относятся к приложению Telegram API, а не к боту.
3. Запустите:

```bash
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail=100 bot
```

Начните с `ACCESS_MODE=admin` и `MAX_CONCURRENT_JOBS=1`. Для обычных пользователей включите `ACCESS_MODE=public` после проверки владельцем. Bot API и базу данных не нужно публиковать в интернет: общение контейнеров не требует свободного порта на хосте.

Бот получает Docker socket ради административного перезапуска контейнеров. Этот доступ даёт значительные права на хосте; для установки без этой кнопки удалите монтирование socket и очистите `RELOAD_CONTAINERS` в Compose.

## Jellyfin, NAS и Proxmox

Подключите хранилище на Linux-хосте и проверьте права. Jellyfin должен читать те же файлы, в которые пишет бот. Укажите в `.env`:

```dotenv
LIBRARY_HOST_DIR=/srv/media/Anime
MEDIA_HOST_ROOT=/srv/media
MEDIA_ROOT=/app/media
JELLYFIN_URL=http://jellyfin:8096
JELLYFIN_API_KEY=
```

`jellyfin` — пример DNS-имени: замените на доступный из контейнера адрес сервера. Ключ создаётся в настройках Jellyfin. Затем:

```bash
mkdir -p /srv/media/.animedl-work
docker compose -f compose.yml -f compose.library.yml config --quiet
docker compose -f compose.yml -f compose.library.yml up -d --build
```

Замените `/srv/media` своим фактическим `MEDIA_HOST_ROOT`; если он не задан — используется `LIBRARY_HOST_DIR`. Каталог `.animedl-work` нужно создать заранее на уже подключённой шаре: `create_host_path: false` запрещает Compose создавать его вместо отсутствующего NAS. Проверьте права чтения файлов пользователем Bot API.

В этом override Bot API получает только рабочий подкаталог `.animedl-work` в режиме чтения, с одинаковым путём в обоих контейнерах. Для файлов владельца из разрешённого каталога используется локальный `file://` без дополнительной HTTP-копии большого видео во временную папку Bot API. Для обычных пользователей остаётся обычная загрузка файла, без использования NAS владельца. Не расширяйте этот mount на всё хранилище. Без такого общего каталога HTTP-загрузка в локальный Bot API может временно занять дополнительное место на его системном диске.

Отсутствующий NAS нельзя заменять пустой локальной папкой: файлы попадут на системный диск. Перед запуском проверяйте `findmnt`. Медиатека сохраняет целый файл, Telegram может получать части. В Jellyfin создайте библиотеки сериалов для Anime/Series и фильмов для AnimeMovies/Movies; фактические имена каталогов сверяйте с `MEDIA_CATEGORIES` в `animedl/models.py`.

Для Proxmox LXC подключите хранилище на хосте и передайте его через свободный mount point. У непривилегированного LXC проверьте UID/GID. Docker требует правильно настроенного nesting; параметры зависят от версии и политики хоста. Bind mount обычно не входит в резервную копию rootfs: медиатеку резервируйте отдельно. Не создавайте новый пул и не форматируйте диски ради переноса. Конфигурацию Jellyfin также сохраняйте отдельно; аппаратное транскодирование необязательно для прямого воспроизведения совместимого файла.

## Сеть: Россия и другие регионы

Проверяйте отдельно сайт-каталог, плеер/CDN, метаданные и Telegram с самого сервера. Некоторые источники требуют российский IP, другие могут быть недоступны из России. Прокси для всего трафика может сломать ранее работавший источник.

Сначала пробуйте прямое подключение. При необходимости задавайте собственный `ALL_PROXY`/`NO_PROXY` и проверяйте маршрут. Некоторые экстракторы используют прямой доступ намеренно. Бесплатные публичные прокси не являются гарантией работы или конфиденциальности. Конфигурация соседнего контейнера на чужом сервере не является обязательной частью установки.

## Ошибки и восстановление

| Симптом | Проверка |
| --- | --- |
| HTTP 403 до скачивания | Регион, доступность источника, сессия плеера. Это не ошибка размера Telegram. |
| Нет ожидаемого качества | Качество для конкретной озвучки/серии, предупреждение о недоступном плеере, повторная проверка. |
| Не скачалась часть серий | Итоговый отчёт и повтор неудавшихся; не обязательно повторять весь сезон. |
| Файл большой | Наличие `ffmpeg`, место под исходник и части, лимит `MAX_TG_MB`. |
| Тайм-аут отправки | Сначала проверьте чат: Telegram мог принять файл, но не вернуть ответ. Повтор может создать дубль. |
| Кэш не сохранил файл | `RETRY_CACHE_MB`, `RETRY_CACHE_HOURS`, свободное место. По умолчанию до 4 ГБ и 24 часов. |
| Не видно серии в Jellyfin | Сканирование, путь, права чтения и фильтр просмотренных. Отметка «просмотрено» сама не удаляет файл. |
| Нет пропуска заставки | Анализ Intro Skipper, поддержка и настройки клиента. Этот необязательный плагин не входит в стек. |

Разделение без перекодирования зависит от ключевых кадров: если один интервал больше лимита, возможна явная ошибка вместо потери кадров или скрытого снижения качества. Кэш ограничен и не заменяет резервную копию. Для отчёта об ошибке сохраните время, источник, серии и обезличенный лог. Не публикуйте `.env`, ключи, cookies или пользовательские базы.

## Ошибки, действия и статистика

Владелец использует `/stats` и `/errors`; другим пользователям эти команды недоступны. Журнал фиксирует действия, результаты загрузки и доставки, источник, качество, размер и категории. Содержимое сообщений, полные URL, ключи и текст исключений в журнал событий не записываются. Идентификаторы пользователей всё же являются данными пользователей: ограничивайте доступ к БД и сообщайте им о сборе статистики.

Локальный ограниченный SQLite-журнал сохраняется и без PostgreSQL. По умолчанию хранится до 50 000 событий и до 30 дней, регулируется `AUDIT_MAX_EVENTS` и `AUDIT_RETENTION_DAYS`. Команды используют PostgreSQL, когда он доступен, иначе явно показывают локальный срез; это не статистика за всё время жизни бота. `AUDIT_ALERTS=0` отключает исходящие уведомления, сохраняя журнал.

Предупреждения и ошибки журналов `animedl` и `aiogram` собираются без текста сообщений и аргументов. `/errors` показывает открытые и решённые проблемы. Закрытие требует успешной проверки той же операции и ресурса: например, всех частей конкретной серии, её миниатюры или записи в PostgreSQL. Успех другой серии и отсутствие новых ошибок не считаются восстановлением. Если надёжной проверки нет, предупреждение остаётся открытым. Старой истории до обновления статусы восстановления не приписываются.

Состояния и очередь уведомлений переживают перезапуск. Уведомление редактируется при восстановлении или повторном открытии. Общий предел — один запрос уведомления за 30 секунд; счётчики открытой проблемы обновляются не чаще раза в пять минут. Поток разных проблем объединяется в сводку. Очередь журналов ограничена 256 записями, список проблем — 500; потери и вытеснения видны в командах владельца. Короткий сбой, завершившийся до первого оповещения, остаётся в истории без отдельного сообщения. После трёх сбоев доставки действует пятиминутная пауза с одной пробой; `429 retry_after` учитывается отдельно. Неопределённый сетевой ответ не даёт гарантии единственной доставки, поэтому повторы и скорость ограничены. Мониторинг не изменяет код бота.

Для отдельного PostgreSQL задайте в `.env` длинный случайный `AUDIT_POSTGRES_PASSWORD` из букв и цифр, затем добавьте override:

```bash
docker compose -f compose.yml -f compose.observability.yml up -d --build
```

Можно одновременно добавлять `-f compose.library.yml`. PostgreSQL 17 Alpine использует отдельный volume и внутреннюю сеть, без порта на хосте: соседний PostgreSQL на 5432 не мешает. Локальные события переносятся в него асинхронно с устойчивыми идентификаторами и повтором после сбоя. В PostgreSQL действует срок хранения и отдельный предел `AUDIT_PG_MAX_EVENTS=100000`; очистка раз в минуту допускает кратковременное превышение. Отдельно сохраняйте резервные копии: журнал не заменяет backup. Alpine — вариант образа, а не ограничение числа пользователей; нагрузку определяют частота действий, запросы и ресурсы сервера.

Наблюдаемость показывает ошибки и статистику. Она не применяет произвольные изменения к коду автоматически: исправления проходят проверку и обычное обновление с возможностью отката.

## Разработка и CI

Нужны Python 3.13, `ffmpeg`/`ffprobe`:

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium --only-shell
python -m unittest discover -s tests -v
docker build -t anime-downloader-check .
```

GitHub Actions выполняет тесты, включая настоящий `ffmpeg`, и сборку образов без секретов. Сайт для CI не нужен. CI не публикует образ и не обновляет сервер: обновление выполняется отдельно после проверки, с резервной копией и откатом.

Проверки внешних источников проводятся отдельно: unit-тесты и короткий фрагмент не подтверждают отправку целого файла больше 2 ГБ. Используйте только материалы, которые вправе скачивать и хранить.

Полная проверка 24 октября 2026: реальный фильм 1080p, **3 110 757 150 байт**,
1920×1080 H.264/AAC, 1:44:53. Без перекодирования созданы части
1 615 322 096 и 1 494 494 732 байт; обе приняты Telegram. Начало и конец
оригинала и частей декодированы со звуком. Отдельно подтверждена передача
части 1,6 ГБ по локальному пути с общей read-only папки без большой копии в `/tmp` Bot API.
Доступность источников и маршрутов может измениться после этой проверки.

## Автоматические исправления парсеров

Опциональный контур `maintenance/` работает отдельно от бота: повторяющаяся ошибка,
предложение внешнего генератора, новый регрессионный тест, полный набор тестов,
CI и проверка запуска. Тесты кандидата изолированы от сети и рабочих данных.
Автоматический допуск ограничен конкретными парсерами/плеерами; доступ, БД,
доставка и зависимости не меняются. Ожидание не вызывает генератор; лимит —
три попытки за 24 часа и одна на группу ошибки/версию исходников.

Перед заменой процесс завершает текущие загрузки. Неуспешный запуск возвращает
прежний образ и исходники; отдельный сторож восстанавливает незавершённую транзакцию
при гибели координатора. При замене единственного polling-процесса есть короткий
перерыв. Это ограниченный автоматический выпуск, а не гарантия исправления любой ошибки.
Без отдельно настроенного генератора и сторожа контур сам не включается.
Операционные зависимости находятся в `requirements-ops.txt`; конфигурацию доступа,
пути и команды провайдера храните отдельно от публичного исходного кода.

Уведомления владельцу содержат ссылку на актуальный username пользователя, если он доступен. После подтверждённого восстановления новой пользовательской операции бот отправляет короткое сообщение с предложением повторить загрузку: не чаще раза в сутки на пользователя, без автоматического скачивания и без рассылки старой истории. Блокировка бота прекращает отправки; неизвестный результат отправки не повторяется. Изменение кода само по себе не доказывает восстановление.

После исправления владелец может выполнить `/recheck КОД_ОШИБКИ`: сохранённая проблемная серия скачивается полностью без отправки пользователю и без записи в медиатеку. Проверяются та же озвучка, качество и ресурс; временный файл удаляется. Только успешная проверка закрывает ошибку источника и включает обычное ограниченное уведомление. Для старых ошибок без сохранённого контекста автоматическое восстановление параметров не угадывается.

Локальный Bot API имеет собственный HTTP idle timeout, независимый от тайм-аута клиента. `TELEGRAM_UPLOAD_PART_MB` (по умолчанию 128 МБ) ограничивает части отправки, даже если весь файл меньше 2 ГБ. Части создаются без перекодирования; прогресс принятых частей сохраняется. При неопределённом сетевом ответе автоматического повтора отправки нет. Перед разделением проверяется запас места.
